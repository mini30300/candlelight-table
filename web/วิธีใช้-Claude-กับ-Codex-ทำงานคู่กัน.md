# วิธีให้ Claude กับ Codex ทำงานคู่กัน (2 ต.ค. 69)

สั่งงานได้สองที่: Claude (claude.ai/code) กับ Codex ของ ChatGPT ทั้งคู่ทำงานกับ repo เดียวกันผ่าน GitHub
แก้โค้ดแล้วเปิด PR ให้คุณกด merge เหมือนเดิม และคุยกันผ่านคอมเมนต์ใน PR

## 1. ตั้งค่า Codex ครั้งเดียว

1. ใช้ ChatGPT แบบเสียเงินที่มี Codex (โควตาแยกจาก Claude ใช้ตอนโควตา Claude หมดได้)
2. เปิด Codex (chatgpt.com/codex หรือแอป Codex) → เชื่อม GitHub → อนุญาตให้เข้าถึง `candlelight-table` กับ `candlelight-server`
3. สร้าง environment ให้แต่ละ repo แล้วใส่คำสั่งติดตั้ง (setup script) ตามนี้ ให้เปิดอินเทอร์เน็ตตอนติดตั้งด้วย (ต้องโหลด Chromium มาเทส)
   - **candlelight-table:** `cd tests && npm ci && npx playwright install --with-deps chromium`
   - **candlelight-server:** `npm ci && cd tests && npm ci && npx playwright install --with-deps chromium`
   - **ไม่ต้องใส่ secret หรือกุญแจอะไรเลย** เทสใช้เซิร์ฟเวอร์จำลองในเครื่อง ส่วนการ deploy ทำเองตอนคุณกด merge
4. ในตั้งค่า Codex → Code review → เปิด **รีวิวอัตโนมัติ** ให้ทั้งสอง repo ทุก PR (ของ Claude ด้วย) จะถูก Codex ตรวจให้

ชื่อปุ่มในหน้า Codex อาจต่างจากนี้เล็กน้อย เพราะ OpenAI เพิ่งปรับหน้าตาเมื่อปลายเดือน ก.ย.

## 2. ทั้งสองตัวรู้กฎได้อย่างไร

ทุกอย่างอยู่ใน repo แล้ว ไม่ต้องอธิบายใหม่ทุกครั้ง

- **`AGENTS.md`** (มีทั้งสอง repo): กฎทั้งหมด Codex อ่านเอง Claude อ่านผ่าน `CLAUDE.md`
  - ห้ามชื่อ Games Workshop / Gundam · ห้ามกุญแจในแชทหรือใน repo · ห้ามบอกวิธีปลดล็อกตัวลับ
  - ภาษาไทยเป็นค่าเริ่มต้น ข้อความใหม่ต้องมีภาษาอังกฤษด้วย · เพิ่มเลขเวอร์ชันและเขียนโน้ตไทยทุกรุ่น
  - ลำดับ merge: server ก่อน table · วิธีทำงานคู่กันและวิธีรีวิว
- **`docs/CODEMAP.md`**: แผนที่โค้ด บอกว่าอะไรอยู่ตรงไหนในไฟล์ใหญ่
- **`tests/`**: เทสทั้งหมดที่ Claude ใช้มาตลอด (โต๊ะรบ 51 ชุด · เซิร์ฟเวอร์กับเว็บ 11 ชุด) รันเองได้ด้วย `bash tests/run.sh`
- **ช่อง "Tests" ใน PR**: GitHub รันเทสให้ทุก PR อัตโนมัติ ใครเปิด PR ก็ถูกตรวจเหมือนกัน

## 3. แบ่งงานยังไงไม่ให้ชนกัน

- **งานละ 1 PR** และอย่าให้สองตัวแก้ส่วนเดียวกันพร้อมกัน (โต๊ะรบเป็นไฟล์เดียวใหญ่มาก แก้พร้อมกันจะชน)
- ตัวอย่างการแบ่ง:
  - Claude ทำโต๊ะรบ · Codex ทำ D&D กับหน้าเว็บ
  - หรือผลัดกัน: ตัวหนึ่งทำ อีกตัวรีวิว
- ก่อนสั่งงานใหม่ ดูว่ามี PR ค้างที่แตะส่วนเดียวกันอยู่ไหม ถ้ามี ให้ merge อันเก่าก่อน
- ข้อความสั่งงานตัวอย่าง (ใช้ได้ทั้งสองตัว):
  > ทำ [งาน] ใน candlelight-table ตามกฎใน AGENTS.md · เปิด PR แบบ draft · รัน `bash tests/run.sh` ให้ผ่าน · เขียนช่อง Handoff ใน PR ให้อีกตัวทำต่อได้

## 4. ให้ทั้งสองคุยกัน

ทั้งสองตัวคุยกันผ่านคอมเมนต์ใน PR บน GitHub

- **Claude เปิด PR → Codex ตรวจ:** ถ้าเปิดรีวิวอัตโนมัติไว้ Codex จะคอมเมนต์เอง (หรือพิมพ์ `@codex review` ในคอมเมนต์) แล้ว Claude อ่านคอมเมนต์และแก้ให้เองใน PR ที่ Claude ดูแลอยู่
- **Codex เปิด PR → Claude ตรวจ:** บอก Claude ว่า "รีวิว PR #เลข ของ Codex ให้หน่อย" Claude จะคอมเมนต์ใน PR จากนั้นพิมพ์ในคอมเมนต์ของ PR ว่า `@codex แก้ตามที่รีวิวไว้` ให้ Codex แก้ต่อ
- **ส่งต่องาน:** ทุก PR มีช่อง **Handoff** บอกว่าทำอะไรไปแล้ว เหลืออะไร อีกตัวอ่านแล้วทำต่อได้ทันที

ข้อจำกัดตอนนี้: Claude จะตอบคอมเมนต์ใน PR ได้เฉพาะตอนที่ session ของ Claude ยังเปิดอยู่
ถ้าอยากให้ Claude ตอบเองตลอดเวลาเมื่อมีคนพิมพ์ `@claude` ใน PR ต้องติดตั้งแอปของ Claude บน GitHub และใส่ secret ซึ่งเจ้าของต้องทำเอง บอก Claude ได้ถ้าอยากทำ

## 5. ก่อนกด merge

- ช่อง **Tests** กับ **Build** ต้องเป็นสีเขียว ถ้าแดงยังไม่ต้องกด สั่งตัวที่เปิด PR ให้แก้
- ลำดับเหมือนเดิม: **candlelight-server ก่อน แล้วค่อย candlelight-table**
- ถ้า GitHub ขึ้นว่า PR ชนกัน (conflict) ให้สั่งตัวที่เปิด PR นั้นว่า "merge main เข้ามาแล้วแก้ conflict"
- ห้ามแปะกุญแจหรือรหัสลับในแชทของทั้งสองตัว
