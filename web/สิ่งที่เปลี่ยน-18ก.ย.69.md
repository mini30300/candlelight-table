## สิ่งที่แก้ในรอบนี้ (สำคัญ)

**1. การเดินไม่ส่ายสะโพกแล้ว** (มินิเลือกระดับ "ไม่ส่ายเลย" — ค่านี้ฝังเป็นค่าเริ่มต้นในโมดูล rig แล้ว)
ค่าที่เปลี่ยนใน `WALK` / `RUN` ของโมดูล SKRIG:

| ค่า | เดิม (WALK) | ใหม่ (WALK) | ใหม่ (RUN) |
|---|---|---|---|
| `sway` แกว่งข้าง (ม.) | 0.022 | 0 | 0 |
| `tilt` สะโพกเอียง (°) | 4 | 0 | 0 |
| `yaw` สะโพกบิด (°) | 5 | 1.5 | 2.4 |
| `footX` ครึ่งความกว้างขายืน (ม.) | 0.055 | 0.036 | 0.0234 |
| `spYaw` / `chYaw` บิดสวนของลำตัว | 0.55 / 1.3 | 0.9 / 0.7 | 1.17 / 0.875 |
| `lean` เอนตัว (°) | 3 | 4 | 12 |

หน้าเว็บยังมีแถวชิป `#skrSway` ให้สลับ 4 ระดับ (ไม่ส่ายเลย / ส่ายน้อย / ส่ายกลาง / แบบเดิม) ผ่าน `setSway()` ถ้าจะเอาระดับอื่นก็แก้ค่าตั้งต้นที่ `setSway('none')` บรรทัดท้าย ๆ ของ `// ==APP==`

**2. แก้บั๊ก "กดตีแล้วกดวิ่ง ขากระโดดพร้อมกัน"**
อาการ: สองขาเข้าเฟสเดียวกัน ยกพร้อม-ลงพร้อม ช่วงลอยตัวพุ่งจาก 39% เป็น 58%
สาเหตุ: ท่าตียืนขาหน้าไปข้างหน้า 0.35 ม. พอเริ่มวิ่งทันที ขาหลังเหวี่ยงไปลงห่างขาหน้าแค่ 0.09 ม. → สองขาล็อกเฟสกันถาวร
แก้ 2 จุดใน `Controller`:
- `leaveAttack()` — ออกจากท่าตีให้เก็บเท้ากลับท่ายืนปกติก่อนทุกครั้ง (ตั้งธง `postAtk`), ระหว่างนั้น `v = 0` และเรียก `settle()` ได้แม้โหมดที่ค้างไว้คือเดิน/วิ่ง แล้วค่อยให้ทางเริ่มเดินปกติ (`moving && this.settled`) ทำงาน
- กฎกันเฟสซ้ำในบล็อกตัดสินยกเท้า: `if (allowed && !over && O.st==='swing' && O.sw < 0.55) allowed = false;`
เคยลองอีกวิธี (คำนวณ `zRef` ของเท้ายืนให้เฟสตรงเลย) — **ใช้ไม่ได้** ทำให้ idle→วิ่ง กระตุก 155 มม. และเดินมีช่วงลอยตัว จึงถอดออก อย่าเอากลับมา

## ตัวเลขหลังแก้ (วัดด้วย node ทั้งหมด)

```
node h3.js skeleton-rig-v4.html      # 18 สถานการณ์เปลี่ยนท่า
node sync_baked.js                   # เฟสของสองขา + ช่วงลอยตัว
```
- เท้าไถลขณะเหยียบ: 0.0 มม. ทุกกรณี (สูงสุด 0.3 มม. เฉพาะตอนเปลี่ยนท่า)
- เดิน: ช่วงลอยตัว 0% (ถูกต้อง) · วิ่ง: 36.7%
- ตี→วิ่ง: เฟสขาซ้อนกัน 6.1% เทียบวิ่งนิ่ง ๆ 6.3% (เดิม 77.6%)
- กระตุกตอนแตะเปลี่ยนท่า: ≤ 26.6 มม.
- ยังค้าง: กดสลับ วิ่ง/ยืน รัว ๆ เฟสขาซ้อน 11.8% (ของเดิมก่อนแก้ 19.3%) — ยังไม่แก้ ไม่กระทบการเล่นปกติ

## โต๊ะรบ (ไฟล์ใหม่ `battle-table.html`)

- พื้น heightfield สุ่มจาก value-noise, 4 ธีม (เมืองพัง / ป่าเนินเขา / ทะเลทราย / ที่ราบหิมะ), ปรับขนาดโต๊ะ 30–260 ม.
- ตึกซากมีหน้าต่าง กำแพงหัก หลุมระเบิด ซุ้มหิน เสาหิน ต้นไม้ ก้อนหิน — วางเป็นกลุ่ม ๆ จากเลขสุ่มของสนาม
- กล้องออร์บิท ลากนิ้วเดียวหมุน สองนิ้วซูม, กล้องไม่จมพื้น
- 1 นิ้วเกม = 1 ม. ในสนาม, โหมดวัดระยะและลากย้ายหน่วยบอกระยะเป็นนิ้วสด ๆ
- ตัวโมเดลใช้ `MINI` = โมดูล armor+kits ที่ฝังในไฟล์ แปลงพิกัดจากเฟรมข้อต่อมาเป็นพิกัดโต๊ะแล้วส่งเข้า `face()` ของหน้าโต๊ะ
- ระยะสายตา: ตัวเล็กกว่า 32 px บนจอวาดเป็นหมากทรงเหลี่ยม, วาดตัวเต็มไม่เกิน 7 ตัว/เฟรม, ตอนลากกล้องตัดเหลือหมากล้วน
- วัดในเครื่องทดสอบ: ฉากไกล 2,265 หน้า 5 ms · ซูมใกล้ 6,163 หน้า 16-18 ms (ยังไม่ได้วัดบน Galaxy A32)

## สิ่งที่ยังไม่ทำ (คิวถัดไป)

1. ให้หน่วยในโต๊ะรบ **เดินจริง** ตอนลากย้าย (ตอนนี้ยืนท่านิ่งแล้ววาร์ป) — ใช้ Controller ต่อหน่วย, cache ท่าไม่ได้แล้ว ต้องจำกัดจำนวนตัวที่อนิเมทพร้อมกัน
2. ปืนสำหรับเกราะหนัก/ทหารราบ (ต้องมีท่าจับสองมือ)
3. สัตว์ / โมเดลไม่ใช่คน
4. ย้ายทั้งชุดเข้าแอพเป็น assets (ตอนนี้ยังเสิร์ฟจาก Worker `/board`) — เพดานขนาด Worker ขยายเป็น 64 MiB แล้ว เรื่องขนาดไม่ใช่ปัญหา แต่ย้ายเข้าแอพจะเปิดเร็วกว่าและเล่นออฟไลน์ได้
5. กติกาการรบแบบ 40k (ยังไม่เริ่มออกแบบ)

## ข้อจำกัดของโปรเจกต์ที่ต้องรู้ก่อนแก้

1. **ห้ามใช้ WebGL / Three.js** — จอดำบนเครื่องของมินิ (ทั้งใน WebView ของแอพและ Chrome) ทุกอย่างวาดด้วย Canvas 2D เขียนเอง
2. **ห้ามใช้ STL/เมชจริง** — เคยลอง ลดเหลือ 300–400 สามเหลี่ยม/ชิ้นแล้วยังกระตุกมากบนมือถือ
3. โมดูลเกราะ/ชุด ต้องแทรก **หลัง** บรรทัด `var R = SKRIG, D = R.D;` เสมอ (ไม่งั้น throw `R is not defined` ตอนโหลด)
4. WebView วัดขนาดได้ 0 ตอนโหลด → canvas ต้องวัดขนาดตัวเองใหม่
5. จำกัดงานต่อเฟรม (โต๊ะรบใช้ 45 ms, แผนที่ก็เช่นกัน)
