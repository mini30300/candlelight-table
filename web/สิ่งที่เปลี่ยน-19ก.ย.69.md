# ชุดอัปเดต Candlelight 3D — 19 ก.ย. 69 (ทำข้อ 1 ของคิวเสร็จ)

ทำต่อจากชุด 18 ก.ย. — **ข้อ 1 ในคิว: หน่วยในโต๊ะรบเดินจริงตอนลากย้าย** (เดิมยืนท่านิ่งแล้ววาร์ป)
แก้เฉพาะ `battle-table.html` — โมดูล `SKRIG` กับ `MINI` ในไฟล์ **ไม่ถูกแตะเลยสักตัวอักษร** (เช็คด้วยการเทียบไบต์)

## ทำยังไง

เพิ่มโมดูลที่สามชื่อ `WALKER` ต่อจาก `MINI` (ไม่ยุ่งกับ DOM เหมือนสองตัวแรก node จึงเรียกไปวัดได้)
หน่วยแต่ละตัวมี `Controller` ของตัวเอง เก็บไว้ที่ `u.ctl`, จุดหมายอยู่ที่ `u.tx / u.tz`

**หัวใจ: ตำแหน่งบนโต๊ะมาจากท่าเดิน ไม่ใช่ท่าเดินมาจากตำแหน่ง**
ทุกเฟรมเอา `ctl.travel` ที่เพิ่มขึ้นมาเป็นระยะที่ตัวเลื่อนไป ไม่ได้ขยับตัวเองแล้วให้ขาตามทีหลัง
ผลคือไม่ว่าเฟรมเรตจะเท่าไร เท้าที่เหยียบอยู่ก็ไม่ไถล เพราะตัวเลื่อนได้เท่าที่ขาก้าวเท่านั้น

**การหันตัว** rig ตรึงเท้าไว้ใน "เฟรมของตัวโมเดล" พอหันตัว เฟรมนั้นหมุนไปทั้งอัน เท้าที่ปักอยู่เลยถูกลากไถลไปด้วย
จึงต้องหมุนของที่แปลว่า "จุดบนโต๊ะ" กลับทางเท่ากันทุกตัว — ไม่ใช่แค่หมุดอย่างเดียว:

| หมุนกลับ | เพราะ |
|---|---|
| `gx` / `gz` | หมุดเท้าที่เหยียบพื้น |
| `a` / `q` / `yaw` | ท่าเท้าปัจจุบัน — `plantHere()` คำนวณหมุดใหม่จากสองตัวนี้ ไม่ได้ใช้หมุดเดิม |
| `a0` | จุดที่เท้าสวิงยกขึ้นจากพื้น (ส่วน `a1` จุดลงเป็นพิกัดเทียบตัว ไม่ต้องหมุน) |

ตอนแรกหมุนแค่ `gx/gz` → เท้าไถล 4.36 มม. เพราะจังหวะเริ่มเดิน controller เรียก `plantHere()`
ซึ่งอ่าน `a`/`q` ที่ยังไม่ได้หมุน แล้วเขียนทับหมุดที่เราเพิ่งหมุนไป

**หันมาก vs หันน้อย** gait generator ของ rig ลงเท้าตรงหน้าสะโพกเสมอ ไม่มีท่าก้าวเลี้ยว
หันเร็วเกินขณะเดิน เท้าที่ปักจะไปอยู่ข้างสะโพก ขาเหยียดสุด กฎ `overreach` ทำงาน (ถูกต้องแล้ว) แล้วปล่อยอีกขาออกก่อนเวลา → ลอยทั้งสองขาในท่าเดิน
จึงแยกเป็นสองแบบ: หันเกิน ~57° ให้ **หยุดหมุนอยู่กับที่** (เท้าขยับทีละข้างกลับมาใต้ตัวด้วย `settle()` เดิมของ rig), น้อยกว่านั้นเลี้ยวไปพร้อมเดิน

## บั๊กที่เจอระหว่างทาง (จดไว้กันลืม)

1. **ปล่อยให้เริ่มเดินตอน `settled` ยังเป็น false ไม่ได้** ตอนหมุนอยู่กับที่ `settle()` จะจัดเท้าสองข้างกลับมาสมมาตรกัน
   ถ้าเริ่มเดินกลางคัน ขาสองข้างจะเข้าเฟสเดียวกัน ยกพร้อมลงพร้อม — **บั๊กเดียวกับที่ชุด 18 ก.ย. แก้ไปแล้วในเคส ตี→วิ่ง**
2. **`if (d)` ใช้เช็ค "มีทิศให้หัน" ไม่ได้** พอหันจนตรงเป๊ะ `d` เป็น 0 พอดี ซึ่ง falsy → หลุดโหมดหมุนกลางคัน (ทำให้เจอบั๊กข้อ 1)
   ต้องแยกเป็น `aim` (มีจุดหมายไหม) กับ `d` (ยังเพี้ยนกี่เรเดียน)
3. **ตัวนับ "เดินไม่คืบ" ต้องไม่นับตอนหมุนอยู่กับที่** ไม่งั้นหมุน 180° ใช้เวลาเกิน 1.5 วิ แล้วโดนยกเลิกจุดหมายทิ้งกลางทาง
4. **หมุนทั้งเฟรมทีเดียวแล้วค่อยเดิน 3 substep ไม่ได้** คู่ หมุน-แล้ว-เดิน จะตรงก็ต่อเมื่อระยะที่เดินเป็นระยะของการหมุนนั้นจริง ๆ
   (เฟรมเรตต่ำ ๆ เท้าไถล 2.59 มม.) → สลับ หมุน-เดิน ทีละ substep
5. **เล็งจุดหมายต่อหลังเริ่มเบรกไม่ได้** เหลือระยะ 8 ซม. ทิศไปจุดหมายแทบเป็นตัวเลขมั่ว ตัวจะหมุนติ้ว ๆ ตอนถึงที่
   → เลิกเล็งตรงจุดที่เริ่มเบรกพอดี

## บั๊กของ rig ที่เจอ (ยังไม่แก้ — ฝากไว้)

**`วิ่ง → เดิน` เป็นการเปลี่ยนท่าเดียวที่ไวต่อเฟส** กดเปลี่ยนตรงจังหวะที่เสี่ยง (วัดได้ 5 จังหวะจาก 61)
ขาสองข้างจะล็อกเฟสกัน แล้ว "ท่าเดิน" นั้นมีช่วงลอยตัวไปตลอดจนกว่าจะเปลี่ยนท่าอีกที (วัดได้ถึง 26.3%)
ส่วน `เดิน → วิ่ง`, `ยืน → เดิน`, `ยืน → วิ่ง`, `เดิน → ยืน` สะอาดทุกจังหวะ (0 จาก 61)

เลี่ยงไปก่อนโดย**ไม่ลดจาก วิ่ง ลงมา เดิน กลางทาง** — เลือกจาก `rem > RUN_AT || c.v > V_WALK` คือถ้ายังเร็วกว่าเดินอยู่ก็วิ่งต่อ
เบรกหยุดทำได้ทั้งสองท่าอยู่แล้ว ตัวที่ออกตัวเป็นวิ่งก็วิ่งยาวจนเบรก
ถ้าจะแก้ที่ rig จริง ๆ ต้องแก้ทั้ง `skeleton-rig-v4.html`, `ctrl4.js`, `battle-table.html` ให้ตรงกัน (โมดูลก๊อปกันอยู่ 3 ที่)

## ตัวเลข (วัดด้วย node ทั้งหมด ไม่ต้องเปิดเบราว์เซอร์)

```
node bt_walk.js            # หน่วยเดินบนโต๊ะ — วัดการไถลใน "พิกัดโต๊ะ"
node h3.js skeleton-rig-v4.html
node sync_baked.js
```

- **เท้าไถลในพิกัดโต๊ะ: 0.00 มม. ทุกเส้นทาง** (สูงสุด 0.32 มม. เฉพาะจังหวะเปลี่ยนท่า = เท่ากับของ rig เปล่า ๆ)
- **ช่วงลอยตัวในท่าเดิน: 0 เฟรม ทุกเส้นทาง** · ท่าวิ่ง ~33% (ถูกต้อง ตามที่ rig ออกแบบไว้)
- หยุดห่างจุดหมาย 1–32 มม. ที่ 60 fps (ระยะเบรก = `v²/2a + 0.033·v` ตัวหลังคือส่วนที่ jerk limiter กินไป วัดได้ค่าเดียวกันทั้งเดินและวิ่ง)
- สะโพกบิดสูงสุด 42.6° (ลิมิตของข้อ 50°) ตอนหมุนอยู่กับที่ — ท่าเดินตรง ๆ บิด 12.3°
- ทดสอบที่ 60 / 30 / 20 / 10 fps: ไถล 0.00 มม. ทุกเฟรมเรต
- ราคาต่อเฟรม: เดิน 1 ตัว 0.024 มส. · ปั้นโมเดลสดต่อตัว 0.20 มส. (570 หน้า) · ตัวแรกที่สั่งเดิน 0.037 มส. ครั้งเดียว
- h3.js / sync_baked.js ได้เลขเดิมเป๊ะทุกบรรทัด (ไม่ได้แตะ rig)

**ลองในเบราว์เซอร์จริง** (Chromium ขนาดจอ 412×820 เท่า Galaxy A32) 11 ตัวเดินพร้อมกัน:
วาดหนึ่งเฟรม median 7.1 มส. / p90 8.1 มส. (เพดานที่ตั้งไว้ 45 มส.) ไม่มี error ใน console

## ของที่เพิ่มเข้าหน้าเว็บ

- ลากหน่วยในโหมด "วางหน่วย" = สั่งให้เดินไปหา ปล่อยนิ้วแล้วมันเดินต่อจนถึง (เดิมวาร์ปตามนิ้ว)
- วงกลมประจุดหมายของตัวที่ยังเดินไม่ถึง · HUD บอก "กำลังเดิน N"
- งบวาดตัวเต็มแจกใหม่: ตัวที่ใหญ่บนจอก่อน และตัวที่กำลังเดินมาก่อนตัวที่ยืนนิ่งขนาดเท่ากัน (ตัวที่วาดเป็นหมากมันโชว์ท่าเดินไม่ได้)
  ปั้นโมเดลสดไม่เกิน 6 ตัว/เฟรม ที่เหลือเดินอยู่แต่วาดเป็นหมาก
- หน้ายังเป็นแบบ "วาดเมื่อมีอะไรเปลี่ยน" เหมือนเดิม — ลูปทำงานเฉพาะตอนมีตัวเดินอยู่ ตัวยืนนิ่งไม่กินซีพียู (ไม่ได้ใส่หายใจตอนยืน เพราะจะทำให้ซีพียูไม่ได้พักเลยบนมือถือ)
- `window.BT.goTo(i, x, z)` / `BT.stop(i)` / `BT.walking()` สำหรับสั่งจากนอกหน้า (แอพ / ตัวทดสอบ)
- `// ==MODULES-BEGIN==` / `// ==MODULES-END==` คร่อม `SKRIG`+`MINI`+`WALKER` ให้ harness ตัด 3 โมดูลออกมารันใน node ได้ (แบบเดียวกับ `==RIG-BEGIN==` ใน `skeleton-rig-v4.html`)

ค่าปรับแต่งอยู่ใน `WALKER.C` ทุกตัว แก้สด ๆ จาก console ได้ ตัวที่น่าจะอยากปรับ:
`TURN` 1.3 (ความเร็วหมุนอยู่กับที่) · `TURN_WALK` 1.6 (หมุนตอนเดิน) · `HOLD` 1.0 (หันเกินเท่านี้ถึงจะหยุดหมุน) · `RUN_AT` 7.0 (ไกลกว่านี้วิ่ง)

## ข้อจำกัดที่ยังอยู่

1. **พื้นเอียงยังไม่รองรับ** ตัวโมเดลคิดว่าพื้นราบเสมอ เดินขึ้นเนินเท้าหน้าจะจมและเท้าหลังลอย
   (ชัน 20% สเต็ป 0.5 ม. → เพี้ยนราว 5 ซม.) ถ้าจะแก้ต้องทำ IK ให้เท้าตามความสูงพื้นทีละข้าง
2. ตัวเดินไม่หลบสิ่งกีดขวาง เดินตรงเข้าหาจุดหมายอย่างเดียว ทะลุตึกได้
3. `วิ่ง → เดิน` ของ rig (ดูหัวข้อด้านบน) — เลี่ยงไว้แล้ว แต่ยังไม่ได้แก้ที่ต้นเหตุ
