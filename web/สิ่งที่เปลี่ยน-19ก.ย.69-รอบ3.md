# รอบ 3 — เกสต์, เล่นบนคอม, และไฟล์ .exe

สองรีโป: `candlelight-server` (Worker) กับ `candlelight-table` (แอพ + เดสก์ท็อป)

---

## 1. ล็อกอินแบบผู้เล่นรับเชิญ (เกสต์)

`POST /api/auth/guest {name?}` → `{token, user{guest:true}}` ไม่ต้องมีบัญชี Google

- `users` มีคอลัมน์ `kind` เพิ่มเข้ามา (`google` | `guest`) เติมด้วย `ALTER TABLE` ครั้งเดียว
  ตอน `ensureSchema` — ฐานข้อมูลที่ใช้งานอยู่แล้วไม่ต้องทำอะไร แถวเดิมทั้งหมดกลายเป็น `google` อัตโนมัติ
  **ทดสอบแล้ว**: แถวที่ใส่แบบไม่มี `kind` อ่านออกมาเป็น `google` และ session เดิมยังใช้ได้
- กันสแปม 2 ชั้น
  - ต่อ IP 20 ครั้ง/นาที (หน้าต่างคงที่ ตาราง `guest_rate`) — เก็บ **แฮชของ IP** ไม่ใช่ IP จริง
    IPv6 ตัดเหลือ 4 กลุ่มแรก เพราะผู้ให้บริการแจกเป็นชุด /64 ต่อบ้าน
  - ทั้งเซิร์ฟเวอร์ 120 เกสต์/ชั่วโมง (`env.GUEST_HOURLY_MAX` ปรับได้) เกินแล้วตอบ 503 `GUEST_BUSY`
- ทุก request ที่ยืนยันตัวตนสำเร็จจะแตะ `users.seen` (เขียนอย่างมากชั่วโมงละครั้งต่อคน)
  เตรียมไว้ให้กฎลบเกสต์ที่หายไป 30 วันในอนาคต
- error ทุกอันมี `code` แล้ว (`AUTH_REQUIRED`, `RATE_LIMITED`, `GUEST_BUSY`, `PAIR_INVALID`, …)
  ฝั่งแอพจะได้แยกกรณีโดยไม่ต้องจับคำไทย

ฝั่งแอพ: ปุ่ม “เล่นแบบผู้เล่นรับเชิญ (ไม่ต้องมีบัญชี)” ใต้ปุ่ม Google พร้อมคำเตือนว่าตัวตนอยู่ในเครื่องนี้เท่านั้น
หน้า “จะเล่นอะไรดี” ขึ้นป้าย “ผู้เล่นรับเชิญ” สีอำพันแทนชื่อบัญชี

## 2. เชื่อมคอมกับมือถือ — รหัสจับคู่

นี่คือคำตอบของ “ให้คอมกับมือถือเชื่อมกันได้” แบบตรงตัว: **บัญชีเดียวกัน** ไม่ใช่แค่ห้องเดียวกัน

| endpoint | ใคร | ทำอะไร |
| --- | --- | --- |
| `POST /api/auth/pair/start` | เครื่องที่ล็อกอินอยู่ | คืนรหัส 8 ตัว (`KTMP-4R9X`) อายุ 5 นาที |
| `POST /api/auth/pair/claim {code}` | เครื่องใหม่ ยังไม่ล็อกอิน | คืน token ใหม่ของ **บัญชีเดิม** |

- ตัวอักษรที่อ่านผิดกันไม่ได้ 31 ตัว (ไม่มี I O L 0 1) สุ่มแบบตัดค่าเกินทิ้ง ไม่เอียงไปตัวต้น ๆ
- `DELETE … RETURNING sub` → ใช้ได้ครั้งเดียวจริง แม้กดสองเครื่องพร้อมกัน
- เครื่องเดิมขอรหัสใหม่ รหัสเก่าถูกลบทิ้ง มีได้ทีละใบ
- จำกัด 20 ครั้ง/นาทีต่อ IP กันเดาสุ่ม (ถึงจะเดาไม่ไหวอยู่แล้ว 31⁸ ≈ 8.5×10¹¹)
- session ใหม่เป็นคนละใบกับของมือถือ — ออกจากระบบเครื่องหนึ่งไม่ลากอีกเครื่องออกด้วย

ในแอพมือถือ: หน้า “จะเล่นอะไรดี” → การ์ด **เล่นบนคอมด้วย** → แตะเพื่อขอรหัส

## 3. `/app` — เล่นบนคอมได้เลย ไม่ต้องลงอะไร

หน้าเดียวจบ เสิร์ฟจาก Worker ตัวเดิม (ฝังด้วย `embed.py` เหมือน `/board`)
ล็อกอิน (Google / เกสต์ / รหัสจับคู่) → ล็อบบี้ (เปิดโต๊ะ, เข้าร่วมด้วยรหัสห้อง, สร้างรหัสจับคู่) → โต๊ะ

กระดานสามมิติคือ `/board` อันเดิมเป๊ะ ๆ ใส่ใน iframe

> `board.html` อ่าน `window.Android` ตอนสคริปต์รันแถวแรก ๆ ยัดทีหลังมันไม่เห็น
> เลยดึง HTML มาเองแล้วแทรกสะพานไว้หลัง `<meta charset>` ก่อนสคริปต์ของหน้า
> (`srcdoc` ใช้ origin เดียวกับหน้าแม่ จึงเรียก `parent` ได้ และ `<!doctype>` ยังอยู่บรรทัดแรก ไม่เข้าโหมด quirks)

ลูกเต๋ายังเป็นกติกาเดิม: เซิร์ฟเวอร์ทอย ทุกเครื่องเล่นซ้ำจาก `seq` เดียวกัน ใครทอยคนอื่นก็เห็นบนโต๊ะ
ตอนโหลดห้องครั้งแรกจะไม่โยนย้อนหลัง (ของเก่าคือประวัติ ไม่ใช่ของใหม่)

Google Sign-In บนเว็บต้องลงทะเบียนโดเมนใน Google Cloud Console ก่อน (ข้อ P0 ของมินิ)
ถ้ายังไม่ได้ทำ ปุ่มจะซ่อนตัวเองแล้วขึ้นข้อความบอกให้ใช้เกสต์หรือรหัสจับคู่แทน — ไม่พัง

## 4. ไฟล์ .exe สำหรับ Windows

`desktop/` เป็นโปรเจกต์ Tauri v2 — หน้าต่างเดียวที่ชี้ไป `/app` บนเซิร์ฟเวอร์
ฝั่ง Rust มีแค่ `main.rs` สิบบรรทัด ไม่มี IPC ไม่มีปลั๊กอิน

- ใช้ WebView2 ที่ Windows 10/11 มีอยู่แล้ว ไฟล์เลยเล็ก (ไม่ใช่ Electron 90 MB)
- อัปเดตหน้าเว็บบนเซิร์ฟเวอร์ = แอพบนคอมได้ของใหม่ทันที ไม่ต้องลงใหม่
- ไอคอน (เทียนกับเปลวไฟ) สร้างจาก `desktop/make-icons.py` — เขียน PNG กับ ICO เองด้วย `zlib`+`struct`
  ไม่ต้องลง Pillow ทำให้รันได้ทุกที่
- `tauri.conf.json` ตรวจแล้วกับ schema จริงของ `@tauri-apps/cli` 2.11.4 — ทุกคีย์ถูกต้อง

CI (`.github/workflows/build.yml`) เพิ่มสองงานบน `windows-latest`

| งาน | เมื่อไหร่ | ได้อะไร |
| --- | --- | --- |
| `windows-check` | pull request | คอมไพล์ให้ดูว่าไม่พัง |
| `windows-release` | push เข้า main | แนบ `.exe` สองแบบเข้า release เดียวกับ APK |

สองแบบคือตัวติดตั้ง (`…_x64-setup.exe`) กับตัวเปล่าที่ก๊อปไปเปิดได้เลย (`candlelight-table.exe`)

## ทดสอบอะไรไปบ้าง

รันจริงบน `wrangler dev --local` + Chromium headless สามเครื่องพร้อมกัน

```
— device 1 (phone-sized) —
  ok   guest login lands in the lobby
  ok   the guest chip is shown
  ok   a room was opened  code=ZEMCR
  ok   the board paints (not a black screen)  ink=18.8%
  ok   the phone can mint a pairing code  THFA-Y7T5
— device 2 (desktop-sized), paired —
  ok   the computer landed on the SAME account  guest_09b3f649…
  ok   the paired device sees the phone's table
— device 3, a different player at the same table —
  ok   a second, separate guest account
  ok   joined by room code
  ok   the board paints on the desktop too  ink=15.2%
— the shared dice —
  ok   the OTHER player saw the roll thrown on the table
  ok   it was a d20 rolled by someone else
  ok   and it is in their log
— javascript errors —
  ok   device 1 / 2 / 3 clean
```

บวกกับที่เช็คด้วย `curl` ตรง ๆ: rate limit ตัดที่ 20/นาทีจริง, รหัสจับคู่ใช้ซ้ำไม่ได้,
รหัสมั่ว ๆ ได้ 404, `pair/start` ที่ไม่มี token ได้ 401, และการ migrate `kind` บนตารางเดิม

**ยังไม่ได้ทดสอบ**: โค้ด Kotlin (คอนเทนเนอร์นี้ไม่มี Android SDK — ต้องรอ CI),
และ `.exe` (ต้องรอ `windows-latest` ใน CI เหมือนกัน)

## ที่มินิต้องทำเอง

1. **deploy Worker** — `cd candlelight-server && npx wrangler@4 deploy`
   (ยังไม่ deploy = ทั้งเกสต์ ทั้ง `/app` ทั้ง .exe ยังใช้ไม่ได้)
2. 🔴 **ตั้ง `DM_KEY`** — `npx wrangler@4 secret put DM_KEY` แล้วต่อ connector ใหม่ด้วย `?key=`
   ตอนนี้ใครมีลิงก์ `/mcp` ก็สั่ง DM ในห้องได้
3. 🔴 **เพิกถอน Cloudflare API token กับ GitHub PAT ตัวเก่า** ที่เคยวางในแชต
4. (ถ้าอยากให้ปุ่ม Google บนเว็บใช้ได้) เพิ่ม JavaScript origin
   `https://candlelight-table.mini3030023450.workers.dev` ใน Google Cloud Console

อย่าวางกุญแจหรือ secret ลงในแชตนะครับ พิมพ์ในเครื่องตัวเองอย่างเดียว
