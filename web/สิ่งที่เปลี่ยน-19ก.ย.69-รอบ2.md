# ชุดอัปเดต Candlelight — 19 ก.ย. 69 รอบ 2 (ย้ายทั้งชุดเข้าแอพ)

ทำต่อจากรอบเช้า (หน่วยเดินจริง) — รอบนี้คือ **ข้อ 4 ในคิว: ย้ายทั้งชุดเข้าแอพเป็น assets**
เดิมแอพโหลดกระดานจาก Worker `/board` ทุกครั้งที่เปิด ต้องมีเน็ตก่อนถึงจะวาดอะไรได้

## ย้ายไปไหน

`web/*.html` → `app/src/main/assets/` แบบ **ย้าย ไม่ใช่ก๊อป** เพื่อไม่ให้มีไฟล์สองชุดคอยเพี้ยนกัน
`web/` เหลือไว้เฉพาะเครื่องวัดผล node กับบันทึกภาษาไทย

| อยู่ที่ | มีอะไร |
|---|---|
| `app/src/main/assets/` | `board.html` (อยู่ที่นี่ตั้งแต่แรก) · `battle-table.html` · `worldmap.html` · `dice-tray.html` · `skeleton-rig-v4.html` |
| `web/` | `bt_walk.js` `h3.js` `harness.js` `sync_baked.js` · `armor.js` `kits.js` `ctrl4.js` · บันทึก 3 ไฟล์ |

harness อ่านหน้าเว็บจาก assets แทน และ `harness.js` ได้ค่าตั้งต้นที่ใช้ได้จริงแล้ว (ของเดิมชี้ไป `rig-v4.html` ซึ่งไม่เคยมีไฟล์นั้น)

## แอพ

**กระดานโหลดจากในเครื่อง** `BoardView` เปลี่ยนไปโหลด `file:///android_asset/board.html`
สำเนาบน Worker เหลือไว้เป็นทางสำรองกรณีโหลดไม่ขึ้น มีธงกันไม่ให้เด้งไปมาระหว่างสองที่
`assets/board.html` เป็นตัวจริงอยู่แล้ว — ทุกคอมมิตที่แก้กระดานในประวัติแตะไฟล์นี้ทั้งหมด ฉะนั้นเปลี่ยนแค่ "โหลดจากไหน" ไม่ได้เปลี่ยนว่า "โหลดหน้าไหน"

> **แลกมาด้วย:** อัปเดตกระดานด้วยการ deploy Worker เฉย ๆ ไม่ได้แล้ว ต้อง build แอพใหม่

**เมนูหลังล็อกอิน** พอล็อกอินเสร็จแอพถามก่อนว่าจะเล่นอะไร
- **D&D** — ห้องแบบเดิม มี Claude เล่าเรื่อง ต้องต่อเน็ต
- **เทเบิลท็อป** — หน้า 3D ในเครื่อง ไม่ต้องต่อเน็ต

คนที่นั่งอยู่ในห้องอยู่แล้วยังเด้งกลับเข้าห้องตรง ๆ เหมือนเดิม เมนูจะโผล่เฉพาะตอนไม่มีห้องให้กลับ
หน้าแรก (lobby) มีปุ่มย้อนกลับมาเมนู จะสลับโหมดไม่ต้องออกจากระบบแล้ว

**หน้าเทเบิลท็อป** เปิดได้ 4 หน้า เต็มจอ ปุ่มย้อนกลับของเครื่องปิดหน้าก่อน แล้วค่อยออกจากหมวด
แต่ละหน้าใช้ WebView ของตัวเอง key ด้วยชื่อไฟล์ เปลี่ยนหน้าแล้วสร้างใหม่ ไม่ทิ้งหน้าเก่าค้างรันอยู่
ไม่มี JS bridge เพราะทั้ง 4 หน้าไม่เรียกกลับเข้าแอพ (ต่างจาก `board.html`)

## บั๊กที่เจอและแก้ (สำคัญ — ข้อจำกัดข้อ 4 ของโปรเจกต์)

**`battle-table` / `worldmap` / `dice-tray` จะจอดำใน WebView**
สามหน้านี้วัดขนาดครั้งเดียวตอนเปิด แล้วฟังแค่ `window.resize` — ซึ่ง**ไม่ยิง**ตอน WebView ถูกวัดขนาดได้จริง
แปลว่า canvas จะค้างที่ 0 px แล้วดำไปตลอด **เป็นบั๊กเดียวกับที่ `board.html` โดนไปแล้วใน 8cd06ed**
ตอนรันในเบราว์เซอร์บนคอมไม่เจอ เพราะขนาดวัดได้ตั้งแต่แรก

ยกวิธีของ `board.html` มาใช้ ปรับให้เข้ากับ canvas ที่ขนาดมาจาก element (ไม่ใช่เต็มจอ):
- ค่าที่วัดได้ต่ำกว่า 2 px ไม่รับ ให้ถอยไปใช้ความกว้างจอ แล้วใช้ความสูงจาก CSS
- วัดใหม่ตอน `resize` / `orientationchange` / `load` / `pageshow` / `visibilitychange` และผ่าน `ResizeObserver` บน canvas
- เช็คซ้ำทุกเฟรม — ไม่เปลืองเพราะถ้าขนาดไม่เปลี่ยนมัน return ทันที

**กับดักที่ตกลงไปเองระหว่างแก้:** ตั้งชื่อฟังก์ชันว่า `measure()` ไม่ได้
`battle-table.html` มี `var measure` อยู่แล้ว (โหมดวัดระยะ) แล้ว `var` จะทับ function declaration ที่ hoist ขึ้นไป
รอบแรกที่แก้ battle-table เลยค้างที่ 300×150 (ค่าเริ่มต้นของ canvas) วาดไม่ออกสักพิกเซล → เปลี่ยนชื่อเป็น `canvasSize()`

## CI

เดิม build เฉพาะตอน push เข้า `main` แปลว่าโค้ดแอพไม่เคยถูกคอมไพล์เลยจนกว่าจะ merge ไปแล้ว
เพิ่ม job `check` ที่รันตอนเปิด PR — `gradle assembleDebug` เฉย ๆ ไม่แตะ signing secret ไม่ออก release
job `build` เดิมไม่เปลี่ยน (push เข้า main กับสั่งมือ)

จำเป็นเพราะ**ในเครื่องที่ Claude ทำงานไม่มี Android SDK และโหลดไม่ได้** (โดนบล็อก) โค้ด Kotlin เลยต้องให้ CI คอมไพล์ให้

## ยังไม่ได้ทำ (คุยกันไว้แล้ว)

1. **ล็อกอินเกสต์** — ทำในแอพอย่างเดียวไม่ได้ auth อยู่ฝั่ง Worker ทั้งหมด (`POST /api/auth/google` คืน token แล้วทุก request แนบ `Authorization: Bearer`) ต้องมี endpoint ฝั่งเซิร์ฟเวอร์ เช่น `/api/auth/guest` — โค้ด Worker อยู่รีโป `mini30300/candlelight-server` (private) มินิกำลังไปหามาให้
2. **ลูกเต๋าที่คนอื่นเห็นด้วย** — **ทำได้โดยไม่ต้องแตะเซิร์ฟเวอร์** ของครบแล้ว:
   - `Api.roll()` ส่งไปเซิร์ฟเวอร์ และเซิร์ฟเวอร์เป็นคนตัดสินเลขอยู่แล้ว
   - ผลไปอยู่ใน `room.log` เป็น entry ที่ `t == "roll"` มี `seq`, `who`, `text`
   - ทุกเครื่อง poll `Api.getRoom(code, seq)` ทุก 2–3 วิ แล้ว merge log ใหม่
   - ที่ขาดคือภาพอย่างเดียว → ให้แต่ละเครื่องจับ entry `t=="roll"` ใหม่ แล้วโยนลูกเต๋าบนกระดานตัวเอง **ใช้ `seq` เป็น seed** ทุกเครื่องจะกลิ้งเหมือนกันและหงายหน้าเดียวกัน (เลขมาจากเซิร์ฟเวอร์ เลยหลุดกันไม่ได้)
   - ฟิสิกส์มีพร้อมใน `dice-tray.html` ย้าย roller เข้า `board.html` หลัง `window.showRoll(...)`
   - **ข้อจำกัด:** คนโยนเห็นทันที คนอื่นช้าได้ถึง ~2 วิ ตามรอบ poll ถ้าอยากพร้อมกันเป๊ะต้องให้เซิร์ฟเวอร์ push หรือลดรอบ poll
3. **โต๊ะรบแบบเล่นร่วมกัน** — ตอนนี้เล่นคนเดียว เติม sync ทีหลังไม่ต้องรื้อ เพราะสถานะหน่วยอยู่ใน `units[]` และเปิดออกทาง `window.BT` แล้ว เซิร์ฟเวอร์ต้องเก็บสถานะโต๊ะเหมือนที่ `board.json` ทำ
4. พื้นเอียงตอนเดิน · ปืน/ท่าจับสองมือ · สัตว์ · กติกา 40k (จากคิวเดิม)
