# วิธีทำโมเดล/แผนที่ในโปรเจกต์ Candlelight (ฉบับส่งต่อให้ AI ตัวอื่นช่วย)

ไฟล์ชุดนี้คือของจริงที่รันได้ เปิดด้วยเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งอะไร ไม่มี library ภายนอกแม้แต่ตัวเดียว
เอกสารนี้อธิบายว่าแต่ละอย่าง "เรียกว่าอะไร" (มีคำอังกฤษให้ค้นต่อ) และ "ทำยังไง"

---

## 1. ตัวโมเดลคน (สติกแมน + ชุดเกราะ) เรียกว่าอะไร

รวมแล้วเทคนิคนี้ชื่อ **software-rendered procedural 3D on Canvas 2D** แยกเป็นชิ้น ๆ ได้แบบนี้

| สิ่งที่ทำ | ชื่อเทคนิค (คำค้น) |
|---|---|
| เขียน 3D เองบน canvas 2 มิติ ไม่ใช้ WebGL/Three.js | software renderer / software rasterizer, painter's algorithm |
| โครงกระดูกข้อต่อพ่อ-ลูก | skeletal rig, bone hierarchy, joint frames |
| หมุนข้อต่อด้วยควอเทอร์เนียน | quaternion rotation, `qmul`, `qrot`, slerp |
| คำนวณตำแหน่งกระดูกจากมุมข้อต่อ | forward kinematics (FK) |
| วางเท้าให้ติดพื้นแล้วคำนวณเข่าย้อนกลับ | inverse kinematics, two-bone IK / analytic leg IK |
| วงจรการเดิน (ยก–เหวี่ยง–ลง) | gait cycle, procedural walk animation, foot phase |
| ตัวโมเดลสร้างจากรูปทรงพื้นฐาน | primitive-based modelling / parametric modelling (dome, tube, quad, box) |
| เกราะเกาะไปกับข้อต่อ | attach to joint frame / local space transform, parenting |
| เรียงลำดับวาดให้ชิ้นหน้าทับชิ้นหลัง | depth sort, painter's algorithm, z-sorting |
| ซ่อนหน้าที่หันหลังให้กล้อง | backface culling (เช็คทิศเวียนของจุดบนจอ = screen winding) |
| แสงเงาแบบง่าย | flat shading, Lambert / N·L lighting, fixed world light vector |
| ลดรายละเอียดเมื่อตัวเล็ก | LOD (level of detail) |

**ลำดับการทำงานในหนึ่งเฟรม** (ไฟล์ `skeleton-rig-v4.html`)

1. คิดความเร็วเดินตอนนี้ (ตัวเลขเดียว มีการจำกัดความเร่ง/อัตราการเปลี่ยนความเร่ง — jerk-limited) → `ctrl4.js`
2. เอาความเร็วไปผสมพารามิเตอร์ท่าเดิน (ความยาวก้าว ความถี่ ความสูงยกเท้า)
3. คำนวณมุมข้อต่อทุกข้อ (FK) + ขาใช้ IK ให้เท้าอยู่ตรงจุดที่ปักไว้บนพื้น
4. โหลดชุดเกราะ: แต่ละชิ้นถูกนิยามในระบบพิกัดของข้อต่อที่มันเกาะอยู่ → `armor.js`, `kits.js`
5. แปลงจุดทุกจุดเป็นพิกัดจอ → ตัดหน้าที่หันหลัง → เรียงตามความลึก → วาด

**หัวใจที่ทำให้ดูไม่ลื่นไถล** (เรื่องนี้แก้มา 4 รอบ): เท้าที่ยืนอยู่ต้อง "ปักหมุด" ไว้กับจุดบนพื้นโลก แล้วให้ตัวเคลื่อนสัมพันธ์กับหมุดนั้น ไม่ใช่ขยับเท้าตามเวลา และเวลาเข่ายืดไม่พอ ให้ "ย่อสะโพกลง" แทนการดึงเท้าเข้า

## 2. ลูกเต๋า

| สิ่งที่ทำ | ชื่อเทคนิค |
|---|---|
| ทรงหลายหน้า d4/d6/d8/d10/d12/d20 | Platonic solids, convex hull, face extraction |
| กลิ้งแล้วกระดอนสมจริง | rigid body dynamics, vertex contact / impulse resolution, restitution + friction |
| ทอยแล้วผลเป็นเลขสุ่มจริง | simulate ก่อนแล้วค่อยเล่นซ้ำ (offline simulation → replay) + **symmetry relabel** = สลับเลขบนหน้าลูกเต๋าด้วยการหมุนสมมาตรของทรงนั้น เพื่อให้หน้าที่หงายขึ้นตรงกับผลสุ่มที่ยุติธรรม |
| เลขติดอยู่บนหน้าเอียง ๆ | text in face plane ด้วย `ctx.transform` |

ไฟล์ `dice-tray.html`

## 3. แผนที่โลก

| สิ่งที่ทำ | ชื่อเทคนิค |
|---|---|
| ภูมิประเทศสุ่มแบบไม่มีขอบ แต่กดซ้ำได้ผลเดิม | procedural generation, deterministic noise จาก integer hash (ไม่ใช้ `Math.random`) |
| noise หลายชั้นซ้อนกัน | value noise + fBm (fractional Brownian motion), ridged multifractal สำหรับสันเขา |
| แบ่งเป็นภูมิอากาศ | moisture map → biome classification |
| แสงเงาภูเขา | hillshade จาก gradient ของความสูง |
| เส้นชั้นความสูง / ชายฝั่ง / แม่น้ำ | marching squares (contour tracing) |
| โหลดเป็นชิ้น ๆ แคชไว้ | tile pyramid, power-of-two zoom levels (2^L เมตร/พิกเซล), LRU cache, frame budget |
| รายละเอียดหยาบ/ละเอียดตามระยะซูม | LOD — ตัดจำนวน octave ของ noise ตามระยะห่างของจุดที่สุ่ม (กัน aliasing) |
| เมือง/ถนน/แคว้น | Poisson-ish site placement per cell, nearest-neighbour road graph, **Voronoi border** (เส้นแบ่งแคว้น = contour ของ ระยะเมืองหลวงที่ใกล้อันดับ 2 ลบอันดับ 1) |

ไฟล์ `worldmap.html`

## 4. ข้อควรรู้ที่เจ็บตัวมาแล้ว (สำคัญมาก ถ้าจะให้ AI ตัวอื่นช่วยต่อ)

1. **WebGL/Three.js จอดำ** บนมือถือเครื่องนี้ (Samsung, ใน WebView ของแอพ และใน Chrome) → ทั้งโปรเจกต์จึงเลี่ยงไปใช้ Canvas 2D เขียน 3D เอง ห้ามแนะนำ Three.js
2. **STL จากไฟล์โมเดลจริงกระตุกมาก** แม้ลดเหลือ 300–400 สามเหลี่ยม/ชิ้น → ใช้วิธีปั้นจากรูปทรงพื้นฐานแทน (~250–300 หน้า/ตัว ลื่นบนมือถือ)
3. WebView ในแอพวัดขนาดได้ 0 ตอนโหลด → canvas ต้องวัดขนาดตัวเองใหม่ (self-sizing)
4. ต้องจำกัดงานต่อเฟรม (เช่น 45 ms) ไม่งั้นเลื่อนแผนที่จะหนืด

## 5. สิ่งที่ยังต้องทำ (โจทย์จริงตอนนี้)

อยากได้ **โต๊ะรบสามมิติแบบ Warhammer 40k** คือกระดานมีขอบ พื้นเป็นภูมิประเทศจริง มีซากตึก/หิน/สิ่งกีดขวางวางอยู่ หมุนดูรอบได้ เอาโมเดลมาวางแล้วตีกันด้วยลูกเต๋า —
ไม่ใช่แผนที่มุมบน และไม่ใช่การเอียงภาพแผนที่ 2 มิติ
ศัพท์ที่ตรงกับของจริง: **battle table / tabletop terrain board, modular scatter terrain, diorama**
ไอเดียที่คิดไว้: ใช้แผนที่โลกใหญ่เป็น "แผนที่ยุทธศาสตร์" เลือกจุดบนแผนที่ → สร้างโต๊ะรบ 3 มิติจากภูมิประเทศจุดนั้น (terrain patch → battle table) แล้วสู้กันบนโต๊ะ
