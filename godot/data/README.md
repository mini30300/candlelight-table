# godot/data — the battle table's data tables as JSON

Generated by `node godot/tools/export_data.js` from `app/src/main/assets/battle-table.html` (APP_VER 9.4, RULES_V 9).
Do not edit these files by hand: change the page and re-run the exporter. `types.json` is read from the live page
(`window.BT.TYPES`, Playwright, `CHROMIUM_PATH` as in `tests/run.sh`); every other table is the literal cut out of the
page source at the CODEMAP anchor named below and evaluated in a Node `vm` sandbox. No helper had to be stubbed and
no table in this export carried a function-valued key, so each file is the complete literal. All Thai strings are kept
as they are; `i18n_en.json` has the English for each of them. Anchors are those of `docs/CODEMAP.md` §2.5–2.6; grep
for them, line numbers drift.

Counts at export time: 274 unit types in 15 armies (plus one `fac:'*'` type usable by every army), 2 hidden units,
272 bot-pool unit keys in `core.json`, 1,554 English strings, 99 budget steps.

## types.json — anchor `var TYPES = [` (CODEMAP §2.6)

The datasheets, as an array in page order. **The array order is a cross-device contract**: an army list travels
between devices and to the server as an array of squad counts indexed by this position, so the port must keep this
exact order and only ever append. Every entry has `k` (unique key; also the figure kit key and the server's `BT2` key),
`fac` (army code from `facs.json`, or `'*'`), `nm` / `d` (Thai name and description), `n` (models per squad), `pts`
(points per squad), `mv` (move in inches), `T` (toughness), `sv` (armour save, n+), `w` (wounds per model), `ld`
(leadership: nerve test 2d6 ≥ ld), `oc` (objective control), `gun` (ranged weapon or `null` = must charge) and `mel`
(melee weapon). Optional per-unit fields seen in this export (count of types carrying each): `inv` 101 (invulnerable
save), `r` 115 (base radius in inches; default 0.8 when absent), `hero` 63, `fly` 60, `brave` 43 (always passes nerve),
`aura` 38 (one of `hit`, `ld`, `bless`, `rez`, `veil`, within `AURA_R`), `ca` 34 (+1 attack after charging), `aoc` 26
(incoming AP −1), `st` 21 (−1 to be hit by shooting), `ac` 20 (charge after advancing), `ttn` 15 (titanic), `ch` 10
(chapter heading, knights; five names, see `chapters.json`), `rez` 10 (self-repair n+), `heal` 8 (heals friends within
3 or 6 inches instead of shooting), `veh` 7, `vsh` 4 (shield layers), `gk` 4 (heals by kills), `hd` 3 (damage halved),
`spawn` 1 (`{k, n}` carried inside, comes out from round 2), `heel` 1 (wound roll 6 kills), `wind` 1 (stands up next
command phase), `sec` 1 and `lk` 1. Weapon objects have `nm`, `a` (attacks per model), `s`, `ap`, `d` and either `rng` +
`bs` (ranged) or `ws` (melee); optional weapon keywords seen: `rf`, `as`, `pi`, `hv`, `su`, `tr`, `lh`, `dw`, `bl`, `po`,
`mk`, `la`, `fx` (effect kind in `fx.json`), `trail`. The Thai legend for all of these is in `rules_summary.md`.
**`inf`** (last field of every datasheet, 1 or 0; 166 / 108 at export time) is not a page field: it is the page's own
`INF(k)` (foot soldier: not a vehicle, mount or creature and scale below 1.5), which the exporter calls on a temporary
copy of the page and writes for every type. The rules core reads it through `GameData.is_inf(k)`; the lint requires it
on every datasheet and forbids `inf: 1` on a vehicle.
**Hidden units**: the page marks them with `sec:1` (one type, `doom`, `fac:'*'`) or `lk:'<army>'` (one type, `tagm`,
locked to army `ta`). Both are free of the points budget (`ptsOf` skips them), limited to one per player outside
spectator mode (`slotMax`, `fitList`) and filtered out of the roster screen (`paintRoster`). How they are unlocked is
intentionally undocumented everywhere in this repository; do not add it here or in the port. The exporter also
evaluates the `TYPES` source literal and compares it with the live array; they were identical, so nothing is added to
a datasheet at runtime.

## facs.json — anchor `var FACS = [` (§2.5)

The 15 armies in UI order: `k` (army code, the value of `fac` in `types.json` and the key of `core.json`), `nm` (Thai
name) and `d` (Thai blurb). The English army names used by the server live in candlelight-server (`BT_ARMY_EN`), not
here; `i18n_en.json` translates the Thai names. Army-wide rules are code, not data (see CODEMAP §2.6 table):
`el` may shoot after advancing (`shotWhyNot`), `de` gets `painOn` from round 3, `cx` gets `pactOn` (melee hit roll 6 =
extra hit), `ta` has designator weapons (`mk`), `kn` has the five chapters. The default army when a list is empty is
`mod` (`facOf`).

## core.json — anchor `var CORE = {` (§2.5, "army building")

Per army code, the ordered list of unit keys the bot (and a Claude seat) builds its army from: `autoList(s, free)`
walks this pool with `seededRoll` from `SEED`, so every device builds the same bot army. 272 keys in all, every one
present in `types.json` (validated by the exporter); hidden units are not in any pool.

## themes.json — anchor `var THEMES = {` (§2.5)

The four maps `ruin`, `forest`, `desert`, `ice`: `sky` (two hex colours, top and bottom of the old gradient),
`ground` / `ground2` / `rock` / `wood` (RGB triplets), `relief` (height amplitude of the heightfield in metres),
`rough` (noise roughness) and `name` (Thai). The server allowlists these names (`BT_THEMES`). The default theme is
`constants.json.theme` (`ruin`). `terrain` overrides `relief`/`rough` in `buildTerrain()` for `flat` and `mountain`.

## terrains.json — anchor `var TERRAINS = {` (§2.5)

The four relief choices `flat`, `hills`, `mountain`, `forest`, each only a Thai `name`; what they do is code in
`buildTerrain()` (flat: relief 0.35, rough 0.45; mountain: relief 11, rough 1.3; forest: hills plus dense woods from
`genProps()`). The server allowlists them (`BT_TERRAINS`). Default `hills`.

## teams.json — anchor `var TEAMS = [` (§2.5)

The 8 team colours in order (team index modulo 8 picks one, `TEAM(i)`): `nm` (Thai), `ui` (hex for UI text) and
`rgb` (triplet used to tint the figures, `teamTint`). Free-for-all and spectator modes use up to all eight.

## phases.json — anchors `var PHASES = [` and `var PHASE_NM = {` (§2.5, §2.7)

`order`: the five phases of a team's turn in sequence (`cmd`, `move`, `shoot`, `charge`, `fight`); `nm`: the Thai
name of each. What happens in each phase is in CODEMAP §2.7 and `rules_summary.md`.

## chapters.json — anchor `var CHAPTERS = {` (§2.5, `paintRoster`)

The five chapters of the power-armour knights (`kn`), keyed by Thai chapter name, which is also the value of a type's
`ch` field: `[plate hex, trim hex, Thai colour description]`. A type with `ch` shows under that chapter heading; types
without `ch` are "common to every chapter".

## variants.json — anchor `var VARIANTS = {` (§2.5, miniatures)

For 19 unit keys, the list of figure kits a squad cycles through so its models do not all look alike: model `j` of the
squad uses kit `list[j % length]` (`kitOf`). The kit names are MINI kit keys (see the kit export); a kit that has no
model falls back to the main one. Cosmetic only.

## skins.json — anchor `var SKINS = {` (§2.5)

Alternative looks a player can pick for a unit: per unit key, an ordered list of `{k: kit, nm: Thai label}`; index 0 is
the default look. The chosen index per unit travels with the army list (`fitSkin`) so every device draws the same.
Only `loki` has a skin so far.

## fly.json — anchor `var FLY_K = {` (§2.5)

Flight look-up for 60 kit keys: `alt` (hover height in metres), `hz` (wing beats per second, 0 = glides), `legs` (1 =
legs dangle/animate while airborne). Flight is cosmetic: rules use the base on the ground. A `fly` type whose key is
missing here uses the `valkyrie` entry (`flyK`). Speeds `FLY_V` / `FLY_A` are in `constants.json`.

## strats.json — anchor `var STRATS = {` (§2.5)

The five command-point stratagems `rr` (re-roll), `ow` (overwatch), `gtg` (go to ground), `gren` (grenade), `brave`:
`nm` (Thai) and `cp` (cost). No function-valued keys exist in this literal; the logic lives in the functions next to it:
`stratKey` (once per team per phase, `brave` once per turn), `canStrat`, `useStrat`, and the pending-roll handlers
`applyGren`, `applyShock`.

## anim.json — anchors `var ANIM = {`, `var TRACER = {`, `var FLAME = {` (§2.5)

`anim`: per kit key, how a figure attacks: `r` (ranged style: `fire`, `bow`, `throw`, `hurl`, `cast`, `beam`, `gaze`,
`spray`, `flame`, `breath`, `lob`, `turret`, `zap`), `g` (gun name used for tracer colour and muzzle), `m` (melee style:
`bash`, `swing`, `swing2`, `thrust`, `lunge`, `claw`, `twin`), `sh` (1 = carries a shield), `hand` (`L`/`R`, which hand
holds the gun). This is the source literal; at load the page copies each base unit's entry onto its variant kits from
`variants.json` when the variant has none (`ANIM[v] = ANIM[k]`), derives `SHIELDED` from `sh`, and `animOf(k)` falls
back to `infantry`. `tracer`: per gun name, `[core hex, glow rgba, width px]`; `flame`: per flame kind, three RGB
strings (core, edge, mid). No function-valued keys were found; the animation logic is `ACT_FN`, `actTick`,
`startAttack`, `die8` (visual only, may use `Math.random`).

## fx.json — anchors `var FXS = {`, `var FX_ST = {`, `var FX_GUN = {`, `var FX_GENERIC = {`, `var MACH8 = {` (§2.5)

`fxs`: the 15 weapon effect kinds. Ranged kinds have `snd` (sound key), `pr` (projectile kind), `spd` (m/s, 0 =
instant), `hit` (impact kind), `fl` (muzzle flash seconds), `sm` (smoke puffs), `cas` (ejected casings), `big`, `en`
(energy), `back` (backblast); melee kinds have `m:1`, `tr` (trail RGB string or null), `mhit` (impact kind) and
`gl`/`wide`/`thin`; `warp` is both. `fx_st`: per ranged kind, `[core hex, glow rgba, width]` used when the gun has no
own `tracer` entry. `fx_gun`: gun name (`anim.g`) → effect kind. `fx_generic`: gun names that take their kind from the
weapon's Thai name instead. `mach8`: kit keys that explode when destroyed (machines); `beast8`: keys excluded from
that even though they carry a turret. No function-valued keys; the matching logic is `fxOf`, `fxGuessGun8`,
`fxGuessMel8` (regexes over Thai weapon names), `machOf`.

## natural.json — anchor `var NATURAL = {` (§2.5, `drawUnit`)

The 26 material names of a figure palette that keep their own colour instead of the team tint (`rigPal`): flesh, coat,
bone, horn, fur, stone, steel, gold, fire… Value is always 1; use the key set.

## unit_colours.json — anchor `var UNIT_COL = {` (§2.5, miniatures)

Explicit palettes for 12 older kits: `plate`, `trim`, `visor`, `base` as RGB triplets. Every other kit gets its palette
from the figure's own solid colours at runtime (`colOf`: `MINI.SOLID[k]`, base `[52,54,60]`), so this file is the
exception list, not the full colour table.

## sky.json — anchor `var SKY = {` (§2.5, backdrop)

Per map: `top` / `hor` (sky gradient hex), `sun` (`[azimuth rad, elevation rad]`), `glow` (RGB string around the sun),
`far` / `near` (skyline silhouette colours), `fog`, `plain` (ground plane beyond the table) and `kind` (`city`, `trees`,
`dunes`, `peaks`: which skyline generator `panoOf` runs, seeded by `SEED`, `PANO_N` samples around the circle).

## dust.json — anchor `var DUST = {` (§2.5)

Per map, the RGB string of the dust a figure kicks up (`dustAt`); `ruin` is the fallback.

## constants.json — anchors `var ENGAGE`, `var CHARGE_R`, `var AURA_R`, `OBJ_R`, `var SLOT_MAX`, `var SPEC_TOTAL`, `var PROP_CAP`, `var RULES_V`, `var APP_VER`, `var BUDGETS = (function(){` (§2.5–2.7)

Rules and layout numbers, inches unless said otherwise (1 game inch = 1 m on the table): `ENGAGE` 1 (base edge to
base edge = engaged), `CHARGE_R` 12, `AURA_R` 6, `OBJ_R` 3 (objective radius) with `VP_PER` 5 and `VP_CAP` 15 (victory
points per objective per turn and the cap), `MAX_ROUND` 5 (default of 3–10) and `KILL_ROUNDS` 30 (goal `kill`),
`DEP_FOE` 20 / `DEP_MATE` 5 (deployment distances), `BLESS_INV` 5 (the `bless` aura's invulnerable save), `REZ_AURA` 4
(the `rez` aura's repair roll), `SLOT_MAX` 99 (squads of one type per player; hidden units 1), `SPEC_TOTAL` 3000
(models on the table in spectator mode; otherwise `baseCap()` = min(250, 500 / players)), `PROP_CAP` 480 (scatter
props), `RULES_V` 9 (the rules version the server gates on; bump it with any rules change), `APP_VER` "9.4",
`GREN_R` 8 (grenade range), `HEAL_ON` 3 (the heal roll, n+), `PAIN_ROUND` 3 (first round of the dark elves' pain
rule); the rules core treats every rules constant as a whole number and a missing one as a load problem. Also the
page defaults `SEED` 1, `theme`, `terrain`, `buildings`, `density`, `table` `{w:48, d:34}` (metres; `d` is derived
from `w` when the table grows), renderer `LODS` and `PANO_N`, flight `FLY_V` / `FLY_A` (m/s), and `BUDGETS`: the 99
values of the points slider that the IIFE builds (200–2,000 by 50, 2,000–10,000 by 250, 10,000–40,000 by 1,000),
exported as the evaluated array. The budget is per team (`shareOf` splits it).

## i18n_en.json — anchor `var BT_I18N = (function(){`, literal `var EN = {` (§2.11)

The English dictionary: 1,554 Thai strings → English, covering UI labels, unit and weapon names, descriptions, log
lines and army names. The page translates by matching the longest keys first inside any Thai text node (`BT_I18N.tr`),
so a key may be a fragment (a unit name, a phrase) rather than a whole sentence; the port should do the same lookup or
translate per field. `tests/battle/english.js` fails when Thai is left on screen in English mode, so every new Thai
string the port shows needs an entry here (added in the page, then re-exported).

## rules_summary.md — anchor `// ═══════════════════ เกม ═══════════════════` to `var TYPES = [` (§2.5–2.6)

Verbatim copy (Thai, with the `//` kept) of the rules summary and the datasheet field legend that precede `TYPES`,
followed by the 37 explanatory comment lines inside the `TYPES` array (ability and weapon keywords added per round,
army section headers). It is the authoritative legend for the fields in `types.json`; the English summary is CODEMAP
§2.6. It contains no unlock instructions for hidden units.
